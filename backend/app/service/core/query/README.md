# Agent 公司识别契约

指代消解、需求理解与规划默认首轮使用 `qwen3.7-flash`，请求异常或输出解析/校验失败后，第二次使用 `qwen3.8-max`；重规划采用同样策略。每个阶段最多两次调用，共用请求预算，预算耗尽不发起兜底请求。正常的澄清结果（包括指代消解返回空 `bindings`）不触发升级；两次失败则沿用现有澄清/规划失败处理。日志记录模型切换，格式正确但语义错误的结果不会自动触发升级。

`AGENT_MODEL`、`AGENT_FALLBACK_MODEL` 控制规划模型；`AGENT_CONTEXT_MODEL`、`AGENT_CONTEXT_FALLBACK_MODEL` 控制指代模型，缺省分别继承规划配置。指代首轮/兜底超时由 `AGENT_CONTEXT_TIMEOUT_SECONDS`（6秒）、`AGENT_CONTEXT_FALLBACK_TIMEOUT_SECONDS`（20秒）配置，并受请求剩余时间限制。在线聊天和离线评测使用相同默认配置，回答与证据核验模型独立配置。

主体由现有 `agent_initial_plan` 模型调用理解，直接保存在各个 `QueryGoal.subjects` 字符串元组中。`QueryUnderstanding` 只持有目标列表和理解状态，不再保存共享实体列表或名称汇总。公司、板块、项目、产品均用完整自然语言描述，不规定实体类型、编号或注册表身份。

- 每个目标的主体随目标直接交给核验模型，无需解析实体引用。主体原文依据复用目标的 `source_spans`，不再单独记录主体引文和字符位置。模型可以消解并规范化主体表达；代码检查文本格式和目标引文真实性，不做名称匹配推断。
- 用户指定的发布方和报告来源保留在目标文本或 `constraints` 中，并体现在检索语句里，不另设发布方引用。
- 目标文本和查询仍应完整表达主体及所属范围，不能只写未消解的“它”或“该板块”。
- `subject_slot` 表示需要前置证据确定的主体；依赖变量必须来自当前任务实际消费的前置证据，不能借用其他分支。
- 任务 `subjects=null` 在计划校验阶段补齐为关联目标的主体元组（没有已知主体时为 `()`），比较目标拆成多个搜索时可原样选择目标主体文本的子集。代码检查选择范围，不允许任务自行替换目标主体。初始规划和重规划统一执行补齐；执行器及重复查询检查直接读取任务主体，动态主体仍在执行时从前置证据绑定合并。
- `RetrievalTask.subject_names` 仅保存自然语言文本，参与缓存区分，并作为上下文进入关键词、向量召回和模型重排。没有主体时不从查询中匹配公司注册表。
- 桥接模型判断主体与值的关系；代码保留来源片段、引文、变量和引用检查，不再按公司名称集合拒绝模型结论。
- 主体归属与证据支持关系由统一核验模型判断。服务端文档范围、租户隔离、预算和任务依赖检查继续保留。

历史注册表文件及独立工具目前保留，但在线理解、检索、核验和报告版本不再依赖它们。入库不生成实体归属标签，旧标签不传入核验；原始公司列、证券代码、表头和行列坐标继续提供给模型，无需重建索引。

回归测试使用固定模型响应覆盖通用主体、板块、发布方、依赖任务、来源校验和缓存区分，不代表真实模型识别率。

主体发现任务的 `output_slot` 必须复用对应目标的 `subject_slot`，补查只更换任务 ID。变量生产者按消费者的直接依赖确定，允许不同轮次复用变量名；同一消费者依赖多个同名输出时拒绝计划。其他桥接变量不必对应目标主体。

`BridgeExtraction` 仅保存 `slot`、`value`、`source_chunk_id`、`document_id`、`source_quote`。模型返回的 `source_chunk_index` 是原始输入证据列表中的 1 起始序号，仅在解析时用于校验和定位，随后转换为稳定片段 ID；不再持久保存序号、提取方式或重复主体字段。
