# Agent 公司识别契约

指代消解、需求理解与规划默认首轮使用 `qwen3.7-flash`，请求异常或输出解析/校验失败后，第二次使用 `qwen3.8-max`；重规划采用同样策略。每个阶段最多两次调用，共用请求预算，预算耗尽不发起兜底请求。正常的澄清结果（包括指代消解返回空 `bindings`）不触发升级；两次失败则沿用现有澄清/规划失败处理。日志记录模型切换，格式正确但语义错误的结果不会自动触发升级。

`AGENT_MODEL`、`AGENT_FALLBACK_MODEL` 控制规划模型；`AGENT_CONTEXT_MODEL`、`AGENT_CONTEXT_FALLBACK_MODEL` 控制指代模型，缺省分别继承规划配置。指代首轮/兜底超时由 `AGENT_CONTEXT_TIMEOUT_SECONDS`（6秒）、`AGENT_CONTEXT_FALLBACK_TIMEOUT_SECONDS`（20秒）配置，并受请求剩余时间限制。在线聊天和离线评测使用相同默认配置，回答与证据核验模型独立配置。

公司名称由 `agent_initial_plan` 的现有模型调用在 `understanding.entities` 中识别，不新增独立 NER 调用。每项包含 `ref`、逐字来自输入问题的 `mention`、`source_quote`，以及引文出现序号 `occurrence`（默认 0）。后端验证来源，计算位置，通过注册表的完整名称/已登记别名精确映射 `entity_id`。位置对应传给 Planner 的 `resolved_question`；历史指代的原始来源保留在 `QueryRequest.bindings` 中。

- 目标用 `subject_refs` 和 `publisher_refs` 分别引用研究主体与发布方，同一实体可以兼任两者。
- `subject_slot` 表示需要前置证据确定的公司，引用任务输出，不能拿本轮实体编号冒充证据变量。
- 任务 `subject_refs=null` 继承目标主体，比较目标拆成单公司搜索时可指定引用子集。
- 目标及任务不再通过关键词覆盖、注册表扫描或分句关系推断拒绝内容改写；实体引用必须存在，任务主体仍必须属于目标。目标可以省略实体全名，背景实体可以不关联目标；文本提及但未引用的实体仅记录诊断。
- 已移除无运行时调用的 `validate_goals`、`validate_relation_bindings` 及其范围推断辅助函数；`validation.py` 仅保留共享异常类型。时间表达改写的回归通过实际规划与工具执行入口验证，不再直接测试旧校验器。
- 实体引文与名称仍须来自原问题。引文中名称出现多次时，保留身份映射及原文，`start/end=-1` 表示无法唯一定位，不任意选择第一次出现；`status` 仍仅描述身份映射状态。
- 目标 `source_spans` 仍逐字验证；约束保留模型输出，不按规则改写“同期”或单位含义，也不生成约束级来源记录。所有需求统一使用目标文本和约束，不再生成财务事实或计算操作数契约；证据是否充分由统一模型判断，计算由回答模型完成。显式文档范围、变量依赖图和工具参数检查继续保留。
- 计划不再强制把目标逻辑依赖映射为任务直接依赖，也不根据“同一报告”“只查研报”等关键词拒绝来源选择。来源要求由 Planner 遵循，显式声明的 `inherit_document_scope` 仍校验并执行。相似查询任务及未关联检索任务的目标只记录诊断，不自动合并、删除目标或认定目标已完成；计划通过不代表最终需求已获得证据支持。
- 执行器构造服务端 `RetrievalTask.company_hints`，名称参与排序，规范化 ID 和状态用于诊断。线索参与缓存键；空线索也显式传递，不能触发从检索语句重新识别。它不生成公司归属过滤，关键词、向量和放宽召回仅保留显式文档、知识库和可用状态等范围。
- 未登记名称与歧义别名保留原名和状态，不猜 ID。片段提到同行或没有实体标签均不会因此被排除；候选仍需经过统一证据核验，检索命中不代表已确认数据归属。
- 本句指代不再由组织后缀规则提前替换；无历史时由初始规划处理，现有历史消解模型可引用历史或当前问题（`source_turn=-1`）。

模型必须显式输出 `entities`，无已知公司时为 `[]`，缺字段会进入已有响应纠错流程。来源校验不能保证模型对名称边界和角色的理解一定正确；未知公司遗漏等语义问题仍取决于模型，需要结合真实评测检查。

兼容范围：未经过 Agent 的独立检索入口及直接构造旧契约的调用方仍可使用查询侧名称识别，但只提供排序线索。`entity_names=None` 表示旧入口；Agent 模型输出使用明确的名称元组（可以为空），不会回退到组织后缀识别。实体配置仍在 `service/core/conf/entity_registry.json`。入库不再生成实体归属标签；旧索引和父表中的历史标签不会传入核验模型，无需重建索引。原始表格的公司列、证券代码、表头和行列坐标继续提供给模型。

回归测试：`tests/unit/test_model_query_entities.py` 覆盖自然语言前缀误判、模型来源校验、多公司关系、发布方、未登记及歧义名称、指代、依赖任务和检索范围传递。测试使用固定模型响应，不代表真实模型识别率。
