# 同表候选分组

查询阶段分为三个不可变对象（`domain.table_retrieval`）：

- `IndexedTableRow`：复制并冻结 ES 来源记录，保留原始 chunk ID。
- `TableCandidate`：保存最终命中行、统一重排分数及成员信息；候选 ID 与
  原始 chunk ID 分离。最终排名最高的入选行作为组代表，输出该行的分数。
- `TableContext`：保存实际展示的行和裁剪诊断，通过命中行集合区分辅助行。
  扩展不会修改候选；父表缺少命中行时保留候选，不静默改用第一行。

Dealer 的 `SearchResult.candidate_fields` 保留来源记录，`table_candidates` 单独传递
最终重排后构建的候选；重排读取每个原始行或正文的语义文本。生产入口把候选对象传给上下文构建器。
旧字典字段仅在 `evidence.table_retrieval_adapter` 输出边界生成，不作为
内部可变状态；`GroupedCandidates.fields` 和旧扩展函数是兼容视图入口。
分层本身不改变 ES 存储；旧表头字段的移除与重新入库要求见下文。

新入库的表格行以 `table_cells_slice_obj.rows` 保存表头、单元格、坐标、
行分组及前置说明（包括单位原文）。不再重复写入顶层
`table_headers_kwd` / `table_cells_kwd`；入库时与通用正文相同的
`table_markdown_excerpt_with_weight` 也不再保存，Markdown 只存于
`content_with_weight`。语义检索文本、向量、定位字段和父表引用继续保留。
解析、检索及输出均统一使用结构化行，`primary_table_row` 不再读取旧顶层
表头和单元格字段。仅含这两个旧字段、缺少结构化行的数据需要重新入库。
检索阶段仍可生成命中行摘录，扩展内容与命中内容的语义区别保持不变。
已有 ES 记录不会自动迁移，重新入库后才使用精简存储。

ES 继续按数据行建立索引。RRF 融合后按排名遍历原始 chunk，使用
知识库、文档、表号和父表引用判断表格身份；未绑定或结构无效的片段
按独立 chunk 计数。同表行不增加候选计数，达到 `rerank_candidate_size`
立即停止，不继续收集后面的同表行。此时只截取 ID，不构建表格对象。

入选前缀中的全部表格行与普通正文统一调用重排模型，保留每行自己的
RRF 分数、语义分数和分支诊断；不执行额外的表内评分或整组重排。
模型提供方按已有批大小分批请求。候选名额不是模型输入条数，同表
多行仍会增加实际评分工作量。

语义名次与第一阶段检索名次继续做第二阶段 RRF，并保留条件冲突降级。
最终排序后采用同样的身份计数循环，选满 `page_size` 个身份立即停止；
截取前缀中的同表行全部保留，之后的行淘汰。不使用语义分数阈值过滤，
`similarity_threshold` 仍用于向量召回，不再过滤最终重排结果。分页按身份跳过前页候选，
前页表格的剩余行不会在后页重新入选。

最终截取后才构建 `TableCandidate`，按最终顺序合并同表行并按行号去重。
不再应用旧的每表 30 行、全局 100 行评分预算或最多 8 个命中行限制。
组证据 ID 由来源和最终行集合生成。`table_candidate_obj.rows` 保存各行
重排分数，`scored_row_indices` 保存同表全部已评分行的语义排序，防止
被截取淘汰的行通过邻域扩展重新加入。组级分数沿用首个入选行，不累加。
语义摘录仍可截断到 1024 tokens，但不因此删除命中行或原始单元格。

评分文本继续附加文档名和可用表题，字段使用 JSON 编码并明确标为来源
上下文。未使用表格对象来拼接多行评分文本，原始记录不被改写。

生产 Agent 的各子查询分别执行上述分组与上下文扩展，随后通过
`EvidenceCollection.merge` 按证据 ID 合并。相同行集合可去重，
不同命中行集合仍是独立证据，目前没有跨子查询的同表重组与重新扩展。
分组工具支持再次合并已有候选，但这项能力尚未接入 Agent 的跨任务合并流程。

父表上下文扩展围绕多个命中行一次完成：邻域/分组取并集，一行只
渲染一次；token 预算不足时优先删除邻行，再删除次要命中行，并记录
`omitted_matched_row_indices`。父表不可用或扩展被关闭时，候选自带的
多行 Markdown 和结构化单元格仍可交给证据适配层。

因上下文容量裁掉的命中行另存为本轮只读恢复快照，包含完整原始列、
表头、分组和单位；低分淘汰行与普通邻行不进入恢复池。快照不作为
当前可用证据，不进入核验、回答或工具的公开证据导出；旧候选元数据
中的遗漏行及摘录也从已交付视图移除，避免绕过裁剪。

Agent 的重规划 observation 提供 `recoverable_rows`：原始行标签、
来源、行号和 `recovery_ref`，不提供遗漏数值。知识库工具存在时注册
`restore_table_rows`，任务的 `query` 逐字填写恢复编号，沿用已有
`goal_ids`；不使用模板或变量依赖。工具只读取本轮已完成知识库搜索
的快照，不接收文件路径、不重读父表；快照固定来源版本，跨运行编号
无效。每次恢复一行，完整内容超过 4096 tokens 时失败，不截断单元格。
恢复计入共享 retrieval 预算，成功结果沿用任务缓存。恢复行作为独立
证据加入 Agent 集合，不再经过原表窗口裁剪，下一轮仍须完成核验。

回答模型对可靠表格只接收结构化视图，不再重复发送 Markdown 正文。
`matched_rows`、`context_rows` 和 `unknown_rows` 分别保存检索命中行、
扩展辅助行和角色未知的行。每行 `values` 中直接配对表头和值，保留
原始列坐标及窗口标记，不假定第一列一定是指标，也不使用表头作字典键
（避免重名列丢失）。优先采用多主行标记，兼容旧版单主行标记。
分组和前置说明原样保留；旧语义文本只去除能确定重建的重复内容，
其余原文放在 `source_notes`，避免丢失单位。结构或坐标不可靠时回退到
原文，并标记 `reliable=false`。前端引用依然展示原始正文。
行分区只描述检索来源，不代表事实已核验；回答仍需核对行名、列头、
主体、期间及单位，也不能直接忽略辅助行中的必要证据。

本次没有对正文设置固定配额，是否入选仍由相关性决定；也没有修改
ES 各检索分支的初始召回上限。分组只能利用已取回的融合池，若两路
召回本身完全被同一张表占满，仍需另行设计 ES 分组召回或受限补取。
此变更不需要重建索引，但历史表头解析错误仍需重新解析原文修复。

验证覆盖同表刷屏后的候选补入、跨来源隔离、多查询命中并集、证据
标识、领域往返、父表多主行展开以及 token 预算控制。
